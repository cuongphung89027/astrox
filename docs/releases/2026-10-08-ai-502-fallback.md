## Problem and behavior

Seven Tu Vi daily requests on 08/10 at 07:32–07:57 Vietnam time failed on DeepSeek after exactly 8,000 output tokens. Four explicitly logged truncation; three logged invalid provider envelopes. Upstream HTTP was 200. Runtime stopped on these validation failures before trying configured fallback routes.

`INVALID_PROVIDER_RESPONSE` and `VISUAL_READING_INVALID` now advance directly to the next configured route, skipping same-provider retries. Strict report validation, policy refusals, input errors, deadline and attempt limits remain enforced. Safe error codes and health failures are recorded; exhausted validation failures preserve the diagnostic.
